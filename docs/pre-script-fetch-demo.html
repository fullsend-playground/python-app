Explore pre-script fetch proof

Verified in a real GitHub Actions run
Explore received data fetched by a trusted Full Send runtime pre-script before the sandbox existed, then read that data during its agent run. No workflow file was edited for this test.

What happened

1. Pre-script fetch The pre-script fetched the public python-app README and wrote a JSON payload.
2. Full Send handoff Full Send copied that directory into the sandbox through the agent_input field.
3. Explore runtime read Explore used the Bash tool in the agent runtime to read the JSON and produce the result file.

Code that makes it work

This follows the documented custom-agent and harness configuration model.

  • pre-explore.sh, lines 4–44 — fetches the README and writes the payload.
  • explore.yaml, lines 22–24 — connects the directory through agent_input and runs the pre-script.
  • config.yaml, lines 15–18 — selects the documented Pi runtime for this Explore proof agent only.
  • explore.md, lines 11–36 — tells the Explore custom agent to read the handoff file and write the result.

Small runtime detail: the agent first tried a write command that repeated the source URL, so Full Send's security hook blocked that command. The agent then read the already-prefetched JSON with Python, wrote the output, and read it back successfully. The artifact records this as an expected security block, followed by six executed tool calls and one extracted output file.
