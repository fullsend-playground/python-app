What we were trying to prove

Putting a skill on a harness skills: list only uploads it. The agent still has to open it with the Skill tool. Team add-on skills often sit in the list and never get opened.

For fullsend ADR 0091 we wanted a reliable way to make selected skills open on every run — without pasting the whole SKILL.md into the agent file.

The approach under test: mark the skill metadata.apply: always, and before the run fill a placeholder in the agent prompt with that skill’s name. The model is told to open those skills with the Skill tool. Bodies stay on disk.

How we tested

Same triage job on this playground repo, nine times total (3 setups × 3 repeats). Each run used a fresh bug issue so triage had a real job to do.

  1. Baseline — normal triage. No extra team skill. Control.
  2. Listed only — add a smoke skill to harness skills: and nothing else. (“Just put it on the list.”)
  3. Always-on — same smoke skill with metadata.apply: always, plus the prompt placeholder filled with its name before the run.

Pass for always-on / listed = transcript shows a Skill open for the smoke skill, and the triage comment starts with the skill’s marker (CAVEMAN:).

Results

Setup Smoke skill opened? Marker in comment?
Baseline (no smoke skill) n/a n/a
Listed only No — 0 of 3 No — 0 of 3
Always-on Yes — 3 of 3 Yes — 3 of 3

Takeaway: listing a skill on the harness is not enough. Always-on (opt-in flag + name in the prompt so the Skill tool opens it) worked every time.
