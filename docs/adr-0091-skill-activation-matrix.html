Did always-on make Caveman run every time?

Yes. On this playground we ran triage with a Caveman skill whose hard rule is: the human-facing triage comment must start with exactly CAVEMAN:.

The skill file path is still skills/smoke-always-on/SKILL.md (playground naming), but the body at the tip we tested is Caveman — see this version (heading # Caveman, rule 7 requires the CAVEMAN: line). An earlier commit at that path was only a PROOF_ALWAYS_ON_SKILL stub and is not what these runs used.

Always-on for this test: metadata.apply: always on that Caveman skill, plus fill its name into the agent prompt before the run so the model opens it with the Skill tool. No pasting the skill body into the agent file.

What “Listed only” vs “Always-on” means

Both setups put a Caveman skill on the triage harness so it gets uploaded into the run. The difference is whether anything forces the model to open it.

Listed only

Add Caveman under harness skills: and stop there. It shows up in the skill list. The model may open it with the Skill tool, or it may ignore it. No flag, no name in the prompt.

  • Harness tip: c93205df triage.yaml — github skills include skills/smoke-listed
  • Skill file: smoke-listed (Caveman body) — no metadata.apply: always

Always-on

Same idea (Caveman must make comments start with CAVEMAN:), but the skill opts in with metadata.apply: always, and before the run the CLI fills __FULLSEND_ALWAYS_ON_SKILLS__ in the agent file with that skill’s name so the model is told to open it.

  • Harness tip: ffbec3c2 triage.yaml — github skills include skills/smoke-always-on
  • Skill file: smoke-always-on (Caveman body) — has metadata.apply: always
  • Agent placeholder: triage.md — contains __FULLSEND_ALWAYS_ON_SKILLS__

Baseline = no Caveman skill at all (control). Three repeats each. Pass = triage comment starts with CAVEMAN:.
